# سرور مستقل کلاس آنلاین فراهوش — انتقال به Cloudflare

این مسیر روی شاخهٔ آزمایشی اجرا می‌شود و **شاخهٔ اصلی را تغییر نمی‌دهد**. Worker به D1 مستقل وصل می‌شود و به Supabase وابستگی ندارد.

## استقرار خودکار از GitHub Actions

در مخزن GitHub وارد **Settings → Secrets and variables → Actions → New repository secret** شوید و این چهار Secret را اضافه کنید:

- `CLOUDFLARE_API_TOKEN`: توکن فعال Cloudflare با مجوزهای حساب `D1 Edit` و `Workers Scripts Edit` (برای ساخت Worker جدید ممکن است نقش مدیریتی محصول Workers لازم باشد). توکن باید برای همان حسابی باشد که `CLOUDFLARE_ACCOUNT_ID` به آن تعلق دارد. گردش کار ابتدا اعتبار توکن و دسترسی به حساب را بررسی می‌کند؛ خطای 401 یعنی توکن نامعتبر/منقضی یا احراز هویت ناموفق است، و 403 معمولاً به مجوز یا محدودهٔ دسترسی مربوط می‌شود.
- `CLOUDFLARE_ACCOUNT_ID`: شناسه حساب Cloudflare.
- `CLASSROOM_MANAGER_PASSWORD`: رمز قوی و محرمانه مدیر مدرسه.
- `NATIONAL_ID_HMAC_SECRET`: کلید تصادفی حداقل ۳۲ نویسه‌ای برای هش HMAC کد ملی؛ پس از ثبت دانش‌آموزان آن را تغییر ندهید.
- `SUPABASE_ANON_KEY`: کلید عمومی پروژه Supabase (در GitHub Actions به‌صورت Secret تنظیم شود). Worker ورود دبیر/مدیر را از Edge Function `classroom-login` می‌گیرد؛ کلید service-role فقط باید در Secrets سمت Supabase بماند.

بعد به **Actions → Deploy Frahoosh classroom to Cloudflare → Run workflow** بروید و شاخهٔ `feat/cloudflare-migration` را انتخاب کنید. گردش کار در صورت نبودن، پایگاه D1 با نام `frahoosh-classroom` را می‌سازد، طرح پایگاه را اعمال می‌کند و Worker و فایل‌های وب را منتشر می‌کند. پس از آن، تغییرات پوشهٔ `cloudflare/` روی همین شاخه انتشار خودکار را فعال می‌کند.

**اگر دکمهٔ Run workflow در رابط موبایل دیده نشد:** پس از ثبت هر چهار Secret، یک commit جدید روی فایل‌های `cloudflare/` در شاخهٔ `feat/cloudflare-migration` نیز گردش‌کار انتشار را به‌طور خودکار اجرا می‌کند. اگر اجرا قرمز شد، ابتدا گزارش مرحلهٔ قرمز را بررسی کنید؛ اجرای مجدد بدون رفع خطا کمکی نمی‌کند.

نام کاربری اولیه مدیر `school-manager` است و رمز از Secret با نام `CLASSROOM_MANAGER_PASSWORD` خوانده می‌شود. هیچ رمز یا کلید واقعی را در مخزن ثبت نکنید.

## فضای ذخیره‌سازی فایل‌ها (R2)

در نسخهٔ فعلی این شاخه، Worker هنوز به R2 متصل نشده و فایل‌های کلاس روی R2 ذخیره نمی‌شوند؛ بنابراین نامشخص بودن وضعیت R2 مانع بررسی اولیهٔ توکن یا ایجاد D1 نیست، اما بارگذاری و نگهداری فایل‌های کلاس تا پیاده‌سازی و آزمون اتصال R2 کامل محسوب نمی‌شود. برای مرحلهٔ R2، باید باکت خصوصی، binding و مجوز `Workers R2 Storage Edit` آماده شوند و سپس بارگذاری/دانلود/حذف فایل‌ها آزمایش شود.

## مسیرهای وب و سلامت

- `/`: صفحه ورود فارسی و پنل موجود
- `/classroom.html`: صفحه کلاس زنده
- `/health`: بررسی پاسخ Worker و اتصال D1

لینک عمومی فقط پس از پایان موفق گردش کار در خروجی مرحلهٔ Deploy مشخص می‌شود. تا آن زمان لینک فعال را فرض نکنید.

## وضعیت و محدودیت‌های مهم

ورود کارکنان در Worker به Edge Function `classroom-login` در Supabase متصل شده است. پس از ورود موفق، فقط شناسه/نقش لازم برای سازگاری با جداول کلاس در D1 نگهداری می‌شود؛ رمز عبور و توکن Supabase در D1 ذخیره نمی‌شوند. برای فعال‌شدن این مسیر، Secret با نام `SUPABASE_ANON_KEY` باید در GitHub Actions ثبت شود. ورود دانش‌آموز با فرم کد ملی هنوز مسیر قدیمی D1 را دارد و در این مرحله مهاجرت نشده است.

این یک **مهاجرت در حال انجام** است، نه تأیید نهایی برای استفاده واقعی مدرسه. بخشی از ورود، نشست، ثبت دانش‌آموز، برنامه و مجوز ورود کلاس در Worker پیاده شده‌اند، اما ورود گروهی Excel، همه گردش‌کارهای پنل و سیگنالینگ امن تخته/رسانه هنوز کامل نیستند. وجود صفحه کلاس به معنی سالم بودن ارتباط دوطرفه صدا و تصویر نیست.

کلاس زنده فعلی از PeerJS عمومی استفاده می‌کند و TURN اختصاصی ندارد؛ بنابراین اتصال رسانه‌ای در همه شبکه‌ها تضمین نمی‌شود. کنترل مجوز تخته، میکروفن و دوربین باید پیش از استفاده رسمی در سمت سرور اعمال و روی دو دستگاه و دو شبکه آزمایش شود. تا پایان آزمون‌های پذیرش فقط داده‌های آزمایشی وارد کنید؛ کد ملی داده حساس است.

## توسعه محلی

از پوشهٔ `cloudflare`:

```sh
npx wrangler dev
```

برای انتشار از گردش کار GitHub Actions استفاده کنید؛ فایل `wrangler.toml` عمداً شناسهٔ پایگاه ساختگی دارد تا شناسهٔ واقعی یا اطلاعات محرمانه در Git ثبت نشود.
